CRASH SITE #1 — HIGHEST PRIORITY
================================================================================

FILE: /Users/jinx/Documents/projeler/CutSense/ios/CutSense/Export/ExportService.swift
LINE: 450
FUNCTION: startProgressTracking(baseProgress:)

CRASH PATTERN:
    progressTrackingTask = Task { @MainActor [weak self] in
        while !Task.isCancelled {
            guard let self, let session = self.exportSession else { break }
            let sessionProgress = session.progress
            self.progress = baseProgress + (0.95 - baseProgress) * sessionProgress
            try? await Task.sleep(for: .milliseconds(250))
        }
    }

ROOT CAUSE:
ExportService is @MainActor (line 5). When startProgressTracking() is called from
exportWithPipeline() which runs on unknown queue context (likely background due to
AVAssetExportSession work), the Task { @MainActor [weak self] } closure captures
@MainActor self on a background thread.

On iOS 26 physical device, Swift 6 strict concurrency inserts dispatch_assert_queue(main)
at the ENTRY of Task when it sees @MainActor capture. If entry point is not main thread:

    EXC_BAD_INSTRUCTION (SIGILL) — dispatch_assert_queue assertion failure

This is NOT caught by Simulator. Physical device only.

EVIDENCE:
- ExportService is @MainActor (line 5)
- startProgressTracking called from exportWithPipeline (line 275)
- exportWithPipeline is async (background execution context unknown)
- [weak self] captures @MainActor self in Task closure

CRASH LOCATION ON DEVICE:
    CutSense Export → Encoding video → Progress tracking starts
    → Task { @MainActor [weak self] in } evaluates
    → dispatch_assert_queue(main) fires
    → CRASH

FIX REQUIRED:
Do NOT capture @MainActor self in Task from unknown queue context.
Use nonisolated static + MainActor.assumeIsolated pattern.

    // BEFORE (CRASHES):
    private var progressTrackingTask: Task<Void, Never>?
    private func startProgressTracking(baseProgress: Float) {
        progressTrackingTask = Task { @MainActor [weak self] in
            while !Task.isCancelled {
                guard let self, let session = self.exportSession else { break }
                ...
            }
        }
    }

    // AFTER (SAFE):
    private var progressTrackingTask: Task<Void, Never>?
    @ObservationIgnored nonisolated(unsafe) private static var _activeExporter: ExportService?

    private func startProgressTracking(baseProgress: Float) {
        ExportService._activeExporter = self
        progressTrackingTask = Task {
            while !Task.isCancelled {
                let currentProgress = ExportService._activeExporter?.exportSession?.progress ?? 0
                let newProgress = baseProgress + (0.95 - baseProgress) * currentProgress
                DispatchQueue.main.async {
                    MainActor.assumeIsolated {
                        ExportService._activeExporter?.progress = newProgress
                    }
                }
                try? await Task.sleep(for: .milliseconds(250))
            }
        }
    }

    private func stopProgressTracking() {
        progressTrackingTask?.cancel()
        progressTrackingTask = nil
        ExportService._activeExporter = nil
    }

RISK: CRITICAL — Crashes app during export on physical device (exact timing of
user-reported "atıyor uygulamadan").

CRASH SITE #6 — BACKGROUND TASK CALLBACK (PATTERN CORRECT BUT FRAGILE)
================================================================================

FILE: /Users/jinx/Documents/projeler/CutSense/ios/CutSense/Export/ExportService.swift
LINE: 469-487
FUNCTION: beginBackgroundTask() / endBackgroundTask()

PATTERN:
    backgroundTaskID = UIApplication.shared.beginBackgroundTask(withName: "CutSense Export") {
        // System is about to kill us — callback runs on background queue
        DispatchQueue.main.async {
            MainActor.assumeIsolated {
                ExportService._activeInstance?.exportSession?.cancelExport()
                ExportService._activeInstance?.endBackgroundTask()
            }
        }
    }

ANALYSIS:
Pattern is CORRECT:
1. Callback runs on background queue ✓
2. Uses DispatchQueue.main.async to dispatch to main ✓
3. Uses MainActor.assumeIsolated for @MainActor state access ✓
4. Uses nonisolated(unsafe) static _activeInstance ✓

FRAGILITY:
1. Optional chaining `?._activeInstance?.exportSession?.cancelExport()` silently
   fails if _activeInstance becomes nil during race condition:
   - Main thread: export completes, sets _activeInstance = nil
   - Background: task deadline fires, callback runs, sees nil
   - Result: export session not cancelled (system kills it anyway, but ungraceful)

2. No logging on race condition — impossible to debug from crash logs

FIX RECOMMENDED (not critical but improves reliability):
    backgroundTaskID = UIApplication.shared.beginBackgroundTask(withName: "CutSense Export") {
        DispatchQueue.main.async {
            MainActor.assumeIsolated {
                if let instance = ExportService._activeInstance {
                    #if DEBUG
                    print("[Export] Background task deadline — cancelling export")
                    #endif
                    instance.exportSession?.cancelExport()
                    instance.endBackgroundTask()
                } else {
                    #if DEBUG
                    print("[Export] Background task deadline but export already ended")
                    #endif
                }
            }
        }
    }

RISK: LOW → MEDIUM — Pattern is correct. Risk is edge case race condition + poor
observability. Not the primary "atıyor uygulamadan" crash.
